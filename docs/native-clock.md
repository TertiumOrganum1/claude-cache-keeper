# Штатный таймер Claude Code

## Зачем

У Claude Code в VS Code есть свой индикатор времени жизни кэша. Он считает от последнего запроса основной ленты, а ответ прогрева туда не попадает, поэтому без правки индикатор показывает, что кэш скоро истечёт, хотя он прогрет. API плагинов не даёт передать индикатору другое время, поэтому плагин может поправить файлы расширения.

После подтверждённого прогрева плагин передаёт время его начала и TTL в штатный счётчик. Ошибка, промах или отсутствие обычного запроса счётчик не трогают. Более поздний обычный запрос или compaction важнее старой отметки прогрева.

## Включение и выключение

Правка выключена, пока пользователь её не включит:

- `/cache-keeper clock on` - включить и наложить правку, затем `Developer: Reload Window`;
- `/cache-keeper clock off` - вернуть оригинальные файлы и больше не накладывать правку, затем `Developer: Reload Window`.

То же из терминала, из каталога плагина:

```sh
python3 scripts/install-clock-bridge.py --check     # проверить совместимость, ничего не меняя
python3 scripts/install-clock-bridge.py --enable    # включить и наложить правку
python3 scripts/install-clock-bridge.py --disable   # выключить и вернуть оригиналы
```

## Что меняется

- `webview/index.js` расширения: вставляется функция, которая передаёт отметку прогрева в счётчик, и callback подтверждения загрузки.
- `webview/index.css`: скрывается заголовок `From the cache-keeper plugin` над строкой.

Расширения ищутся в `~/.vscode/extensions` и `~/.vscode-insiders/extensions` по их `extensions.json`. Состояние хранится в `~/.claude/cache-keeper/`:

- `bridge-enabled` - отметка, что пользователь включил правку;
- `patched.json` - пропатченные копии расширения: версия, размер и время изменения `index.js`;
- `backups/<версия>-<время>/` - оригинальные `index.js` и `index.css`.

## Обновления расширения

После включения плагин вызывает установщик один раз при каждом запуске. Если версия, размер и время файла совпадают с `patched.json`, файл даже не читается. Новая версия расширения или переустановка той же версии меняют эти данные, и правка накладывается заново.

Привязки к конкретной версии нет: имена минифицированных переменных определяются по структуре компонента. Если обновление изменило нужный код, установщик ничего не меняет, в строке появляется «Таймер Claude: несовместимая версия», а прогрев продолжает работать.

## Безопасность правки

- Перед записью проверяются структура bundle и синтаксис результата (`node --check`).
- Оригиналы копируются в `backups`, замена пишется атомарно.
- Несколько чатов, стартующих одновременно, используют общую файловую блокировку.
- Частичная или чужая правка не затирается: установщик сообщает о конфликте.
- CLI, закрепление версии расширения и его автообновление не меняются.

## Подтверждение загрузки

Правка на диске и правка в открытом окне - разные вещи: уже открытое окно продолжает работать со старым кодом. Загруженный webview подтверждает поддержку через скрытый callback своего чата, без запросов к модели. До подтверждения строка показывает «Таймер Claude: перезагрузи окно». Окно плагин сам не перезагружает.

## Откат вручную

Если команда недоступна: удалите плагин, скопируйте `index.js` и `index.css` из нужного каталога `~/.claude/cache-keeper/backups/` в `webview/` расширения и выполните `Developer: Reload Window`. Переустановка расширения Claude Code тоже возвращает исходные файлы.

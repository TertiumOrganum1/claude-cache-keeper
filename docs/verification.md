# Проверка Cache Keeper 0.2.6 (2026-10-16)

- 52 нативных теста Claude Code: 52 pass, 0 fail.
- TypeScript: tsc --noEmit без ошибок.
- claude plugin validate --strict: пройден для plugin, marketplace, hooks и state contract.
- Настоящий CLI + отдельный config + локальный fake API: обычный запрос и fork, запущенный таймером, содержат одинаковые TTL 1h, model, tools, system, effort и префикс messages. При выключенном плагине запрос только один, стандартный TTL 5m. К провайдеру запросы не отправлялись; API usage синтетический.
- GUI AbovePrompt проверен через ui.mount: переключатель, немедленный запуск, счётчик и время; окна не открываются. Survey проходит дальше.
- Компоновка дерева установленного исходника с CSS расширения в headless Chrome: одна строка при ширине 720, 1080, 1440 px; на 720 px горизонтальная прокрутка, на 1080 px всё помещается. Скриншот: gui-preview.png. Это отдельный браузерный стенд, а не снимок действующего VS Code.
- Review выявил busy-guard при reload и старый таймер при session replacement. Добавлены регрессии и исправления: busy сохраняется, активный GUI запрещает startup/manual fork, session.end отменяет таймеры и сбрасывает модуль.

Часовое продление кэша на реальном Anthropic API в этой проверке не измерялось. Таймер показывает расчётное время на основе request start; успешным прогревом считается только подтверждённый usage cache hit. Ошибки и промахи останавливают автоматику до ручного повтора или следующего обычного хода.

Дополнение 0.2.3: в настоящем GUI-логе после ответов зарегистрированы lastAt/TTL/cache read, но статус оставался waiting. Регрессия без отдельного prompt.submit воспроизвела ту же комбинацию. Удалены устаревшие зависимости от lastHumanAt из reason/canSend, оставшиеся от отменённого idle-limit, и все ui.toast. Новые тесты проверяют SDK-запрос без метки пользователя, восстановление такого состояния и отсутствие всплывающих уведомлений.

Дополнение 0.2.4: настоящий GUI-лог показал, что нажатие доходило до model.fork, но процесс отвечал `no main-thread response to fork yet`. Добавлены объяснение этой ситуации, состояние кнопки во время запроса и регрессия повторного клика. Идемпотентный enable больше не обесценивает успешный ответ уже выполняющегося прогрева.

Связь со штатным таймером проверена отдельно на коде установленного расширения 2.1.300: настоящий AbovePrompt effect вызывает callback session host, тот обновляет promptCacheRecord, а нативная функция расчёта Mm меняет остаток с 57m на 60m. Проверены защита более позднего обычного запроса/compaction, отказ для будущих отметок, повторный рендер без изменения, идемпотентная установка и отказ при несовпадении структуры bundle. Это изолированная проверка кода webview; живой интерфейс VS Code загрузит его после Reload Window.

Дополнительный review подтвердил привязки useEffect/session host и выявил необходимость проверки session id. Маркер теперь содержит $.session.id(), callback сравнивает его с нативным sessionId.peek(); проверка со старым деревом другого чата воспроизвела ошибку до исправления и проходит после.

Графическая ветка принудительно включена только в одноразовой копии исходника. Живой UI всё ещё требует Reload Window для загрузки новых файлов.

Дополнение 0.2.6: в ротированном GUI-логе Claude VSCode.1.log за 2026-10-16T16:45:24Z прогрев завершился за 5687ms с input=14, output=3, cacheRead=357202, cacheCreate=1626. Последний обычный запрос содержал input=2, read=356681, write=521, output=1626. Старый код отвергал этот кэш-хит из-за cap 1024 новых токенов и прекращал последующие прогревы. Входной хвост не равен ответу на прогрев.

Проверка теперь сравнивает чтение с отдельным mainUsage исходного запроса; fork его не меняет. Регрессии проверяют настоящий набор счётчиков и два цикла GUI, хвост 30000 токенов с повторным циклом после save/restore, отказ при чтении 5000 из исходных 20000, отказ при нулевом чтении и отображение счётчиков именно неудачного fork. lastRefreshUsage сохраняется отдельно, включая отказ. Старое состояние без новой схемы использует main baseline только если до этого не было успешных fork; иначе применяется проверка без известной исходной длины.

Нативный transport probe повторяет счётчики инцидента через локальный HTTP-сервер и проверяет, что plugin принял прогрев и не подменил mainUsage. Это воспроизведение записанного случая; новый платный прогрев реального чата и многочасовое продление у провайдера в ходе исправления не выполнялись.

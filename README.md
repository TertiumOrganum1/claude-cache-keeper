# Cache Keeper

Плагин Claude Code, который держит prompt cache чата тёплым в графическом чате VS Code. Нужен Claude Code с поддержкой mods; проверено на 2.1.300.

![Строка Cache Keeper над полем ввода](docs/screenshot.png)

## Установка

```sh
claude plugin marketplace add TertiumOrganum1/claude-cache-keeper
claude plugin install cache-keeper@tertium-cache-keeper --scope user
```

Затем `Developer: Reload Window` в VS Code. Над полем ввода появится строка: контекст, процент чтения кэша, лимиты 5h и 7d, модель, переключатель `Кэш: вкл/выкл`, время следующего прогрева и кнопка `Прогреть`.

Прогрев включён по умолчанию, но начинается только после первого ответа Claude в чате: после перезапуска VS Code старые чаты сами ничего не отправляют. Выключить прогрев в чате - переключатель в строке или `/cache-off`. Каждый прогрев - запрос к модели и расходует лимиты подписки или API.

Необязательно: чтобы штатный индикатор кэша Claude Code учитывал прогревы, выполните в чате `/cache-keeper clock on`. Эта команда правит файлы расширения Claude Code (webview/index.js и webview/index.css), оригиналы сохраняются. `/cache-keeper clock off` возвращает их. Подробности - в разделе «Штатный таймер VS Code».

Обновление плагина: `claude plugin marketplace update tertium-cache-keeper`, затем `claude plugin update cache-keeper@tertium-cache-keeper --scope user`.

## Команды

- `/cache-keeper` или `/cache-status` - подробное состояние, usage, время следующего запроса и ошибка.
- `/cache-on`, `/cache-off` - прогрев в текущем чате.
- `/cache-keeper now` - немедленная попытка.
- `/cache-keeper on 5m` или `/cache-keeper on 1h` - выбор TTL для последующих запросов.
- `/cache-keeper clock on`, `/cache-keeper clock off` - правка штатного таймера расширения.

## Как работает прогрев

Прогрев - вызов `model.fork` с коротким ответом поверх контекста чата: весь контекст читается из кэша, новых токенов почти нет. В пустом чате, а также после перезапуска VS Code до нового обычного ответа API возвращает `nothing-to-fork`: запрос к модели не отправляется, строка объясняет, что нужен ответ Claude. Кнопка `Прогреть` запускает попытку сразу и показывает `Прогреваю...`; повторный клик не отменяет текущий запрос; переключатель `Кэш: вкл/выкл` управляет только этим чатом.

Основные запросы и прогревы используют явный одинаковый TTL `1h`, если настройки Claude его разрешают. Плагин проверяет срок каждые 15 секунд и отправляет запрос за 5 минут до истечения. В режиме `5m` - за одну минуту. Успех подтверждается usage: не менее 1024 токенов cache read и покрытие не менее 95% известного входа последнего обычного запроса. Промах или ошибка не превращаются в фиктивный успешный таймер: причина видна в строке, повтор доступен кнопкой. Перезагрузка кода плагина сохраняет состояние в host-owned session state; закрытие VS Code, сон компьютера и остановка процесса исключают выполнение таймеров. Уже истёкший кэш автоматически не пересоздаётся.

Изменение модели, effort, состава инструментов или контекста отменяет старый отсчёт. Временные переменные TTL восстанавливаются после запроса. Запрос не пересекается с другим прогревом; запоздалый ответ не перезаписывает состояние нового пользовательского хода.

## Проверка

```sh
npm test
npm run test:clock
npm run test:repair
npm run typecheck
npm run validate
npm run probe
```

`probe` запускает настоящий CLI с отдельным временным config и фиктивным API-ключом против локального HTTP-сервера. Проверяет фактический запуск fork таймером, TTL main/fork, модель, инструменты, system prompt, effort и префикс сообщений. Usage в этой проверке синтетический: она не доказывает часовой срок хранения у провайдера и не отправляет платных запросов. Для проверки GUI используется нативный `ui.mount` и отдельная проверка компоновки в Chrome с CSS установленного расширения.

Версия 0.2.3 устраняет ложное ожидание первого ответа в GUI/SDK: готовность к прогреву определяется последним успешным запросом и его TTL, без обязательной метки ручного ввода. Всплывающие уведомления на ответы и прогревы удалены; состояние остаётся в строке.

## Штатный таймер VS Code

После подтверждённого cache hit плагин передаёт время начала прогрева и его TTL в штатный счётчик Claude через локальную правку webview расширения. Обычный API плагина этого не делает: ответ fork не появляется в основной ленте, которую слушает штатный счётчик. При ошибке, промахе или отсутствии исходного запроса счётчик не сбрасывается. Более поздний основной запрос или compaction имеет приоритет перед старой отметкой прогрева.

Правка выключена, пока пользователь не выполнит `/cache-keeper clock on`. То же из терминала:

```sh
python3 scripts/install-clock-bridge.py --check     # проверить совместимость, ничего не меняя
python3 scripts/install-clock-bridge.py --enable    # включить и наложить правку
python3 scripts/install-clock-bridge.py --disable   # выключить и вернуть оригиналы
```

После включения плагин при каждом запуске вызывает установщик один раз. Пропатченные версии записываются в ~/.claude/cache-keeper/patched.json: версия расширения, размер и время изменения webview/index.js. Если всё совпадает, bundle не читается и не правится. Новая версия расширения или переустановка той же версии меняют запись, и установщик накладывает правку заново. Расширения ищутся в ~/.vscode/extensions и ~/.vscode-insiders/extensions по extensions.json. Имена минифицированных переменных определяются по структуре компонента и React binding. Если обновление изменило нужные контракты, в строке появится сообщение о несовместимости, а прогрев продолжит работать.

Установщик проверяет структуру bundle и синтаксис кандидата, сохраняет исходные JS/CSS в ~/.claude/cache-keeper/backups, записывает замену атомарно и использует общую файловую блокировку для нескольких чатов. Частичная или неизвестная правка не затирается. CLI, закрепление версии расширения и автообновление не меняются.

Откат: `/cache-keeper clock off` восстанавливает последние сохранённые оригиналы для текущей версии расширения и больше не накладывает правку; затем `Developer: Reload Window`. Если копии нет, переустановите расширение Claude Code.

Наличие правки на диске проверяется отдельно от её загрузки. Загруженный webview подтверждает поддержку через скрытый UI callback своего чата без запроса к модели. До подтверждения строка показывает "Таймер Claude: перезагрузи окно"; переход в другой чат предупреждение не теряет. Если старый интерфейс уже открыт, выполните `Developer: Reload Window`: плагин не перезапускает окно во время вашей работы.

Оба таймера показывают оценку по времени запроса, а не остаток, полученный от сервера. Успешное чтение кэша проверяется по usage; изменение цифр до 60m само по себе не доказывает часовой срок хранения у провайдера.

Версия 0.2.6 исправляет ложный отказ после успешного прогрева: read 357202 / write 1626 / input 14 / output 3 ошибочно отвергались старым ограничением новых токенов. Процент cache и подробные счётчики теперь относятся к последнему прогреву даже при отказе, а не к предыдущему обычному ответу. Восстановление состояния сохраняет исходный вход и поддерживает последующие циклы с большими хвостами.

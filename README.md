# Cache Keeper

Локальный плагин Claude Code для прогрева prompt cache в GUI VS Code. Требуется Claude Code с поддержкой mods; работа проверена на 2.1.300.

Версия 0.2.6 показывает компактную строку над полем ввода: контекст, процент чтения кэша, лимиты подписки 5h и 7d (до получения данных - ?), модель, кнопку включения, время следующего запроса и число успешных прогревов. Отдельных окон и персонажа нет. Строка не переносится; в узкой панели доступна горизонтальная прокрутка.

Прогрев включён по умолчанию. При загрузке в уже существующий чат плагин один раз пытается вызвать `model.fork` с коротким ответом. В пустом чате, а также после перезапуска VS Code до нового обычного ответа API может вернуть `nothing-to-fork`: запрос к модели не отправляется, строка объясняет, что нужен ответ Claude после запуска VS Code. Наличие старой истории само по себе недостаточно. Кнопка `Прогреть` запускает попытку сразу и показывает `Прогреваю...`; повторный клик не отменяет текущий запрос; переключатель `Кэш: вкл/выкл` управляет только этим чатом.

Основные запросы и прогревы используют явный одинаковый TTL `1h`, если настройки Claude его разрешают. Плагин проверяет срок каждые 15 секунд и отправляет запрос за 5 минут до истечения. В режиме `5m` - за одну минуту. Успех подтверждается usage: не менее 1024 токенов cache read и покрытие не менее 95% известного входа последнего обычного запроса. Ответ и результаты инструментов после этого входа могут добавить любой объём новых токенов: абсолютного ограничения на их запись в кэш нет. Исходный вход хранится отдельно и не подменяется счётчиками fork. Если исходный вход ещё неизвестен, используется доля чтения не менее 95% от входа самого fork. Промах или ошибка не превращаются в фиктивный успешный таймер: причина видна в строке, повтор доступен кнопкой. Лимитов в три прогрева и три часа нет. Перезагрузка кода плагина сохраняет состояние в host-owned session state; закрытие VS Code, сон компьютера и остановка процесса исключают выполнение таймеров. Уже истёкший кэш автоматически не пересоздаётся.

Изменение модели, effort, состава инструментов или контекста отменяет старый отсчёт. Временные переменные TTL восстанавливаются после запроса. Запрос не пересекается с другим прогревом; запоздалый ответ не перезаписывает состояние нового пользовательского хода. Каждый прогрев расходует лимит подписки/API.

## Команды

- `/cache-keeper` или `/cache-status` - подробное состояние, usage, время следующего запроса и ошибка.
- `/cache-on`, `/cache-off` - управление прогревом.
- `/cache-keeper now` - немедленная попытка.
- `/cache-keeper on 5m` или `/cache-keeper on 1h` - выбор TTL для последующих запросов.

## Установка из локального репозитория

```sh
git clone https://github.com/TertiumOrganum1/claude-cache-keeper.git
claude plugin marketplace add ./claude-cache-keeper
claude plugin install cache-keeper@tertium-cache-keeper --scope user
```

Автообновление VS Code/CLI и закрепление их версий плагин не меняет. Видимый заголовок `From the cache-keeper plugin` добавляет расширение Claude Code, а не сам плагин. На машине пользователя для этой панели установлен узко направленный CSS override; обновление расширения может его стереть.

## Проверка

```sh
npm test
npm run test:clock
npm run test:repair
npm run typecheck
npm run validate
npm run probe
```

`probe` запускает настоящий CLI с отдельным временным config и фиктивным API-ключом против локального HTTP-сервера. Проверяет фактический запуск fork таймером, TTL main/fork, модель, инструменты, system prompt, effort и префикс сообщений. Usage в этой проверке синтетический: она не доказывает часовой срок хранения у провайдера и не отправляет платных запросов. Для проверки GUI используется нативный `ui.mount` и отдельная проверка компоновки в Chrome с CSS установленного расширения.

Версия 0.2.3 устраняет ложное ожидание первого ответа в GUI/SDK: готовность к прогреву определяется последним успешным запросом и его TTL, без обязательной метки ручного ввода. Всплывающие уведомления на ответы и прогревы удалены; состояние остаётся в строке.

## Штатный таймер VS Code

После подтверждённого cache hit плагин передаёт время начала прогрева и его TTL в штатный счётчик Claude через локальную правку webview расширения. Обычный API плагина этого не делает: ответ fork не появляется в основной ленте, которую слушает штатный счётчик. При ошибке, промахе или отсутствии исходного запроса счётчик не сбрасывается. Более поздний основной запрос или compaction имеет приоритет перед старой отметкой прогрева.

```sh
python3 scripts/install-clock-bridge.py --check
python3 scripts/install-clock-bridge.py
```

Начиная с 0.2.5, при запуске графического чата и затем каждые 5 минут плагин сам вызывает установщик. Он находит зарегистрированные версии расширения в ~/.vscode/extensions и ~/.vscode-insiders/extensions по extensions.json. Фиксации на 2.1.300 нет: имена минифицированных переменных определяются по структуре компонента и React binding. Если обновление сохранило нужные контракты, правка восстанавливается автоматически. Если изменило их - в строке появится сообщение о несовместимости, а прогрев продолжит работать.

Установщик проверяет структуру bundle и синтаксис кандидата, сохраняет исходные JS/CSS в ~/.claude/cache-keeper/backups, записывает замену атомарно и использует общую файловую блокировку для нескольких чатов. Частичная или неизвестная правка не затирается. Компактная строка без заголовка плагина тоже восстанавливается. CLI, закрепление версии расширения и автообновление не меняются.

Наличие правки на диске проверяется отдельно от её загрузки. Загруженный webview подтверждает поддержку через скрытый UI callback своего чата без запроса к модели. До подтверждения строка показывает "Таймер Claude: перезагрузи окно"; переход в другой чат предупреждение не теряет. Если старый интерфейс уже открыт, выполните `Developer: Reload Window`: плагин не перезапускает окно во время вашей работы.

Оба таймера показывают оценку по времени запроса, а не остаток, полученный от сервера. Успешное чтение кэша проверяется по usage; изменение цифр до 60m само по себе не доказывает часовой срок хранения у провайдера.

Версия 0.2.6 исправляет ложный отказ после успешного прогрева: read 357202 / write 1626 / input 14 / output 3 ошибочно отвергались старым ограничением новых токенов. Процент cache и подробные счётчики теперь относятся к последнему прогреву даже при отказе, а не к предыдущему обычному ответу. Восстановление состояния сохраняет исходный вход и поддерживает последующие циклы с большими хвостами.
